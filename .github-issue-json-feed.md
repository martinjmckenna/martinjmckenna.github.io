# Explore JSON Feed as an alternative/complement to Atom feed

## Overview
Explore implementing JSON Feed as a modern alternative or complement to our existing Atom feed (`feed.xml`).

## What is JSON Feed?

JSON Feed is a modern syndication format introduced in 2017 as an alternative to RSS and Atom. It uses JSON instead of XML, making it easier to work with in modern web development.

**Specification:** https://www.jsonfeed.org/version/1.1/

## Why JSON Feed vs RSS/Atom?

### Advantages of JSON Feed:
- **Simpler format**: JSON is easier to parse than XML for most developers
- **Native JavaScript support**: No XML parsing libraries needed
- **Better for modern apps**: Most APIs use JSON today
- **More extensible**: Easy to add custom fields
- **Human-readable**: Easier to debug and understand
- **Type-safe**: JSON has clear types (strings, numbers, booleans, arrays)

### Why RSS/Atom Still Matters:
- **Universal support**: All feed readers support RSS/Atom
- **Established ecosystem**: Decades of tooling and infrastructure
- **SEO**: Search engines understand RSS/Atom better
- **Backward compatibility**: Most users expect XML feeds

### The Modern Approach:
**Offer both formats.** JSON Feed for modern apps/developers, Atom/RSS for traditional readers.

## Current State

We currently have:
- `feed.xml` - Atom 1.0 feed with last 10 posts
- Basic fields: title, link, updated, id, content

## Implementation Plan

### Phase 1: Research & Design (1-2 hours)
1. **Review JSON Feed specification v1.1**
   - Understand required vs optional fields
   - Review extension mechanisms
   - Check GitHub Pages compatibility

2. **Analyze current feed structure**
   - Map existing Atom fields to JSON Feed equivalents
   - Identify fields we want to add (tags, authors, featured images, etc.)
   - Determine if we need custom extensions

3. **Research Jekyll plugins**
   - Check if `jekyll-feed` supports JSON Feed
   - Look for dedicated JSON Feed plugins
   - Evaluate manual implementation vs plugin

### Phase 2: Create JSON Feed Template (1-2 hours)
1. **Create `feed.json` file**
   - Use Liquid templating (similar to our `feed.xml`)
   - Set `layout: null` to prevent wrapping
   - Set proper content type via front matter

2. **Map fields from Atom to JSON Feed**
   ```
   Atom              → JSON Feed
   -----------------------------------
   <title>           → title
   <link>            → home_page_url
   <id>              → feed_url
   <updated>         → (not in top level)
   <entry>           → items[]
   <entry><title>    → items[].title
   <entry><link>     → items[].url
   <entry><updated>  → items[].date_modified
   <entry><id>       → items[].id
   <entry><content>  → items[].content_html
   ```

3. **Add enhanced fields**
   - `summary` - Post excerpt
   - `tags` - Post tags array
   - `authors` - Author information
   - `image` - Featured image if available
   - `date_published` - Original publish date

### Phase 3: Add Discovery & Links (30 mins)
1. **Update HTML head in layout**
   - Add `<link>` tag for JSON Feed discovery
   - Keep existing Atom feed link
   ```html
   <link rel="alternate" type="application/feed+json" href="/feed.json" />
   <link rel="alternate" type="application/atom+xml" href="/feed.xml" />
   ```

2. **Add footer/sidebar links**
   - Link to both feeds
   - Explain the difference for users

### Phase 4: Testing (30 mins)
1. **Validate JSON Feed**
   - Use https://validator.jsonfeed.org/
   - Test locally with `jekyll serve`
   - Verify all fields render correctly

2. **Test in feed readers**
   - Check readers that support JSON Feed (NetNewsWire, Feedbin, etc.)
   - Verify content displays properly
   - Test URLs are absolute and correct

3. **Check GitHub Pages deployment**
   - Ensure JSON file is served with correct MIME type
   - Verify both feeds are accessible

### Phase 5: Documentation (15 mins)
1. **Update README**
   - Mention both feed formats available
   - Link to feed files

2. **Consider blog post**
   - Explain why we offer both formats
   - Tutorial for developers who want JSON Feed

## Example JSON Feed Structure

```json
{
  "version": "https://jsonfeed.org/version/1.1",
  "title": "{{ site.title }}",
  "home_page_url": "{{ site.url }}",
  "feed_url": "{{ site.url }}/feed.json",
  "description": "{{ site.description }}",
  "icon": "{{ site.url }}/assets/icon.png",
  "favicon": "{{ site.url }}/favicon.ico",
  "authors": [
    {
      "name": "{{ site.author.name }}",
      "url": "{{ site.author.url }}"
    }
  ],
  "language": "en-US",
  "items": [
    {
      "id": "{{ site.url }}{{ post.url }}",
      "url": "{{ site.url }}{{ post.url }}",
      "title": "{{ post.title }}",
      "content_html": "{{ post.content | jsonify }}",
      "summary": "{{ post.excerpt }}",
      "date_published": "{{ post.date | date_to_xmlschema }}",
      "date_modified": "{{ post.date | date_to_xmlschema }}",
      "authors": [
        {
          "name": "{{ post.author }}"
        }
      ],
      "tags": {{ post.tags | jsonify }}
    }
  ]
}
```

## Technical Considerations

### Content Type
- GitHub Pages should serve `.json` with `application/json`
- May need to verify in deployment

### Escaping
- Use Liquid's `jsonify` filter to safely escape JSON
- Be careful with quotes in titles/content

### Feed Size
- Consider limiting to same 10 posts as Atom feed
- Or offer "full archive" JSON feed separately

### Backward Compatibility
- Keep `feed.xml` as primary feed (most compatible)
- Add JSON Feed as "bonus" for modern readers

## Decision Points

1. **Manual template vs plugin?**
   - Manual = More control, no dependencies
   - Plugin = Easier maintenance, if one exists

2. **How many posts in feed?**
   - Match Atom feed (10 posts)
   - Or provide more/all posts?

3. **Custom extensions needed?**
   - Reading time
   - Post series information
   - Code language tags

4. **Update existing posts to add metadata?**
   - Authors
   - Featured images
   - Better excerpts
